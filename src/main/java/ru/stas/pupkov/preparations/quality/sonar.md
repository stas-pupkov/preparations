## 1. Что такое Sonar

**SonarQube** (часто просто «Sonar») — платформа статического анализа: код, дубли,
smells, уязвимости, покрытие тестами. В CI обычно: собрать → прогнать тесты с
JaCoCo → `sonar-scanner` → Quality Gate pass/fail.

Это **не** замена code review и **не** доказательство, что тесты хорошие.

---

## 2. Что обычно меряют

| Область | Примеры |
|---------|---------|
| Bugs / Vulnerabilities | NPE-риски, injection, слабая криптография |
| Code smells | длинные методы, дубли, слишком сложные условия |
| Duplication | copy-paste |
| Coverage | строки/ветки, покрытые тестами (часто JaCoCo) |
| New code | правила жёстче на **новый** diff, чем на весь легаси |

---

## 3. Тесты и coverage

Типичная связка:

```text
JUnit-тесты → JaCoCo exec → отчёт coverage → Sonar импортирует
```

Sonar показывает:

- overall coverage;
- coverage on new code;
- иногда uncovered lines на PR.

**Coverage 80% ≠ хорошие тесты.** Можно покрыть геттеры и не проверить оплату заказа.
Sonar не понимает бизнес-смысл сценария.

Полезнее на собесе говорить так:

- unit — быстрые инварианты домена;
- slice / integration — Spring + БД;
- contract — совместимость API между сервисами.

Sonar это не классифицирует — только «строка исполнялась или нет».

---

## 4. Quality Gate

Набор порогов: «если на new code coverage < 70% или есть blocker — пайплайн красный».

Пример политики:

- 0 blocker / critical на new code;
- coverage on new code ≥ 70%;
- duplicated lines on new code < 3%.

Легаси часто не гонят к 90% сразу — давят на **новый** код.

---

## 5. Ловушки

1. Гнать coverage ради процента (тесты без assert'ов).
2. Игнор issues через `// NOSONAR` без причины.
3. Падать Quality Gate только на overall coverage монолита — боль, лучше new code.
4. Путать Sonar bugs с реальными прод-багами: это эвристики.

---

## 6. Вопросы для собеседования и ответы

### 1. Что Sonar говорит о тестах?

В основном coverage и иногда тестовые smells. Качество сценариев, мутационное тестирование,
флаки — вне зоны «зелёной цифры».

### 2. Почему gate на new code, а не на весь проект?

Легаси тянет процент вниз годами. Правило «новый код не хуже порога» реалистичнее для
живого продукта.
