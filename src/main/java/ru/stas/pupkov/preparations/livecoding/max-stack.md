# Max Stack: push / pop / peekMax за O(1)

## Условие

Написать класс-стек с методами:

- `push` — положить элемент;
- `pop` — снять верхний элемент;
- `peekMax` — вернуть максимальный элемент в стеке за **O(1)**.

На собесе обычно подразумевают, что `push` и `pop` тоже **O(1)** (иначе задача тривиальна: хранить один max и при его удалении сканировать весь стек).

## Ключевая идея

Одного поля `max` недостаточно: при `pop` текущего максимума нужно знать предыдущий max без линейного поиска.

Решение: **вспомогательный стек максимумов** (или хранить пары `(value, maxSoFar)`).

На каждом `push(x)` в `maxStack` кладём `max(x, текущийMax)`. Тогда:

- `peekMax()` = `maxStack.peek()` — O(1);
- `pop()` снимает оба стека — O(1);
- `push()` — O(1).

Память: O(n) дополнительно.

### Оптимизация по памяти

В `maxStack` класть значение только когда `x >= currentMax`. При `pop` снимать из `maxStack` только если снятый элемент равен текущему max. В худшем случае (монотонно возрастающая последовательность) всё равно O(n), в среднем — меньше дубликатов.

## Типичные ошибки кандидата

- Пересчёт max через `stream().max` / цикл при `pop` → **O(n)**, нарушает договорённость.
- `compare` вместо `compareTo`; raw `Comparable` / raw `LinkedList`.
- Непроговорённые edge cases: пустой стек, дубликаты максимума, `null`, контракт `compareTo`.

## Вопросы для собеседования и ответы

**Все ли операции обязаны быть O(1)?**  
Формально в условии указан только `peekMax` O(1). Но если `pop` может быть O(n), задача сводится к «храним max и при его удалении ищем заново». Интервьюер почти всегда хочет amortized/worst-case O(1) на всех трёх операциях.

**Как обработать дубликаты максимума?**  
Вариант с дублированием max на каждый push: дубликаты безопасны. Вариант «класть max только при `>=`»: при `pop` снимать max только при равенстве снятому значению — тоже корректно для нескольких одинаковых max.

**Можно ли без второго стека?**  
Можно хранить в узле пару `(value, maxBelowOrSelf)` или односвязный список своих узлов. Суть та же: история максимумов должна жить вместе с элементами.

**Что с generics?**  
`T extends Comparable<? super T>` — стандартный bound (как в `Collections.max`). Для `Integer`/`String` достаточно; для своих типов — корректный `compareTo` и согласованность с `equals`.
