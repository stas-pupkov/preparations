# Число без пары: HashMap vs XOR

## Условие

В массиве все числа встречаются **по два раза**, кроме **одного** — найти его.

Пример: `[1, 0, 3, -2, 9, 9, 1, -2, 0]` → **3**

## Решение на собесе: XOR

```java
int unique = 0;
for (int num : arr) {
    unique ^= num;
}
return unique;
```

Свойства: `a ^ a = 0`, `a ^ 0 = a`, XOR коммутативен/ассоциативен → все пары обнуляются, остаётся одиночка.

- Время O(n), память O(1).
- Работает и для отрицательных (`int` в dual complement).
- Допущение: ровно один элемент с нечётной частотой (здесь — ровно один одиночный, остальные ×2).

## Вариант с HashMap (идея ок, код на скрине сломан)

Счётчик частот → найти key с count == 1. O(n) время, O(n) память.

Ошибки в черновике:

| Место | Баг |
|-------|-----|
| `new HashMap<>;` | нет `()` |
| `for (int i = 0, i++, i < arr.length())` | запятые вместо `;`, condition/update, `length` не метод |
| raw `HashMap` / `Entry` | типы |
| `entry.value()` | нужно `getValue()` |
| `optionaResulr` | опечатка |
| `throw ...` | псевдокод |

`findFirst` по entrySet **HashMap** не гарантирует порядок — для «единственного» с count==1 порядка не нужно, ок.

## Вопросы для собеседования и ответы

**Если какое-то число встречается 3 раза?**  
XOR даст неверный смысл «пары»; нужна другая постановка (частоты / битовые счётчики для «один раз при остальных по три»).

**Почему не сортировка?**  
O(n log n); XOR линейный и без доп. памяти.
