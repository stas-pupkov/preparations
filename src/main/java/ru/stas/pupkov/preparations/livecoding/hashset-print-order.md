# Что выведет `HashSet` при `println`?

## Условие

```java
Set<String> leaders = new HashSet<>(Arrays.asList("Сталин", "Ленин", "Че Гевара"));
System.out.println("Leaders = " + leaders);
```

## Ответ

Формат:

```text
Leaders = [элемент, элемент, элемент]
```

**Порядок элементов внутри `[]` не определён** и **не обязан** совпадать с порядком в `asList` (`Сталин`, `Ленин`, `Че Гевара`).

`HashSet` не гарантирует iteration order (в отличие от `LinkedHashSet` / `TreeSet`). `toString()` у `AbstractCollection` просто обходит iterator — какой бакет/порядок хэшей получился, такой и вывод.

На конкретной JVM/версии часто стабильно один и тот же порядок для тех же строк, но опираться на него в ответе и в коде нельзя — это не контракт API.

Пример одного из возможных выводов (JDK 17, один прогон):

```text
Leaders = [Че Гевара, Сталин, Ленин]
```

Любая перестановка трёх уникальных строк — корректный результат.

## Вопросы для собеседования и ответы

**Почему не как в `Arrays.asList`?**  
`asList` даёт `List` с порядком вставки. `HashSet` кладёт элементы по `hashCode` в таблицу; обход — по бакетам, не по истории `add`.

**Как получить стабильный порядок в выводе?**  
`LinkedHashSet` (порядок вставки), `TreeSet`/сортировка (natural/`Comparator`), или явно `stream().sorted()` перед печатью.

**`String` equals/hashCode тут ни при чём для «пропажи» элементов?**  
Все три строки различны → size = 3. Вопрос только про порядок в `toString`, не про дедупликацию.
