# Первый неповторяющийся элемент в массиве

## Условие

Найти первый элемент, который встречается ровно один раз.  
Пример: `{9, 4, 9, 6, 7, 4, 5}` → **6** (порядок «первого» — по первому появлению в массиве).

## Идея на собесе

1. Подсчитать частоты (HashMap) **или** сразу LinkedHashMap count + порядок вставки.
2. Пройти в порядке первого появления, вернуть ключ с count == 1.
3. Если нет такого — договорённость (`-1`, `Optional`, exception).

`LinkedHashMap` удобен: сохраняет порядок первого `put`.  
Сложность: O(n) время, O(k) память (k — уникальные).

Два прохода по массиву + HashMap тоже ок и часто яснее на whiteboard.

## Что сломано в коде со скрина

Идея верная, до запуска далеко:

| Место | Проблема |
|-------|----------|
| `new LinkedHashMap<>;` | нет `()` |
| `for (i = 0; i++; i < arr.length())` | нет `int i`; condition/update перепутаны; у массива поле `length`, не `length()` |
| `void main` + `return key` | так нельзя |
| `Optional<Entry>` | сырой тип; лучше `Optional<Map.Entry<Integer,Integer>>` или сразу `int` |

После правок синтаксиса алгоритм дал бы **6** (как в комментарии к map).

## Вопросы для собеседования и ответы

**Почему не обычный `HashMap` + один проход по массиву?**  
Можно: второй проход `for (x : arr) if (count.get(x)==1) return x`. Порядок «первого в массиве» сохраняется. `LinkedHashMap` — сахар, не обязателен.

**Стрим `filter/findFirst` по entrySet LinkedHashMap?**  
Корректно при insertion-order. На обычном HashMap порядок entrySet не определён → «первый» будет неверным.

**Ограничения по диапазону значений?**  
Если числа в маленьком диапазоне — массив частот; если огромный/разреженный — map.
